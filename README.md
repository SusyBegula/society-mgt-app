# Neighbourly · Society management



English-first management app for multiple Indian housing societies, with resident, society-office and guard workflows. React Native / Expo for Android and iOS, a browser office interface, and a FastAPI / PostgreSQL backend. Each society collects maintenance through its own configured payment account.

Includes society onboarding, flat imports, membership approvals, billing rules and ledgers, expenses and bank matching, refunds, visitor approvals and QR passes, parcel pickup, emergency response, notices, amenities, documents, assets, meetings, advisory polls and privacy requests. Read the [operations guide](documentation/operations-release.md) for setup, scope boundaries and launch requirements.

## Requirements

- Node 22.13+ and npm; the lockfile pins Expo SDK 57 / React Native 0.86.
- Docker with Compose; Python 3.12+ for environment setup.
- Android SDK, JDK 17, and an authorized USB-debugging phone for local Android builds.
- macOS/Xcode for local iOS builds, or an Expo account and EAS Build.

## Local setup

```bash
python3 scripts/setup-env.py
docker compose --profile local-db up -d db
```

The setup script creates missing environment files and preserves existing ones. Check the target database before migrations or seeding. For the API container, configure `backend/.env` with `DATABASE_URL=postgresql+psycopg://society:society@db:5432/society` and `STORAGE_PATH=/data/uploads` when using the local Compose database and uploads volume. Then:

```bash
docker compose up -d --build api
docker compose exec api python -m app.seed
cd mobile
npm ci
```



Backend: `http://127.0.0.1:8000`; development API docs: `/docs`; readiness: `/health`. PostgreSQL is exposed locally on `55433`. Compose applies Alembic migrations before starting the API. Seed data is development-only and idempotent; it creates Green Heights / Tower A / Flat 1204 and Sunrise Residency / Tower C / Flat 305.

**Demo login:** mobile `9876543210`, OTP `123456` (India +91). Use the property selector to choose either home. Directory contacts other than public emergency numbers are demonstration numbers.

## Connected Android phone

```bash
adb devices -l
bash scripts/android-usb.sh
cd mobile
export ANDROID_HOME="$HOME/Android/Sdk" # adjust to your SDK path
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk # adjust as needed
npm run android
```

Select the connected phone. The initial native build can take several minutes. This installs an **Expo development build**, not Expo Go. No emulator is needed. After installation, subsequent JS changes need only Metro:

```bash
npm start -- --localhost
```

If needed, open the USB-forwarded server explicitly:

```bash
adb shell am start -a android.intent.action.VIEW -d 'exp+society-resident://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8081' com.society.resident
```

Repeat port forwarding after reconnecting USB. The development API URL is supplied through `mobile/.env`; for physical iOS or Wi-Fi use `http://YOUR_COMPUTER_LAN_IP:8000`, and start Metro with `npm start -- --lan`. The API listens on `0.0.0.0` through Docker.

## Environment configuration

Use the two `.env.example` files as the reference. Real `.env` files are ignored.

| Setting | Purpose |
| --- | --- |
| `APP_ENV` | `development` locally; keep both `ALLOW_DEMO_AUTH` and `ALLOW_DEMO_PAYMENT` false for live deployments. |
| `DATABASE_URL` | PostgreSQL SQLAlchemy URL. Use host `db:5432` inside Compose or `127.0.0.1:55433` for a host API using the local DB. Compose reads this setting as configured. |
| `JWT_SECRET` | Random secret of at least 32 characters, generated by setup. |
| `SMS_URL`, `SMS_TOKEN` | Production HTTPS SMS adapter accepting `{phone, message}` with bearer authentication. |
| `PAYMENT_PROVIDER` | `development` locally or `razorpay`. Use Razorpay test credentials for sandbox payments. |
| `RAZORPAY_ACCOUNTS` | Server-only JSON map of society UUID to merchant key ID, secret and webhook secret. Webhook: `/payments/webhook/{society_id}`. |
| `RAZORPAY_SOCIETY_ID` | Explicit society assignment required if using the legacy global Razorpay credentials. |
| `PLATFORM_ADMIN_USER_IDS` | Server-only JSON list granting access to platform subscription management. |
| `STORAGE_BACKEND` | `local`, `supabase` or `s3`; configure the corresponding storage credentials. |
| `EXPO_PUBLIC_API_URL` | Device-accessible API base URL; production must use HTTPS. |
| `EXPO_PUBLIC_EAS_PROJECT_ID` | EAS project ID for push registration. Android production push also needs your FCM credentials configured with EAS. |

Razorpay checkout is included in the native development client. The backend creates orders, verifies signatures and captured amounts, processes signed webhooks, and reconciles interrupted payments. The development payment button is explicitly labelled and collects no money. Receipts and documents open the device share/save menu for PDF export.

## Migrations and backend development

```bash
docker compose exec api alembic upgrade head
docker compose exec api python -m app.seed
docker compose logs -f api
```

For backend development without the API container:

```bash
docker compose stop api
docker compose --profile local-db up -d db
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install --no-deps -e .
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

For a host API, set `DATABASE_URL` to the host-accessible URL and `STORAGE_PATH=./uploads` before running the commands above. Create schema changes with `.venv/bin/alembic revision --autogenerate -m description`, review the generated migration, then apply it. Uploads live in object storage / the Docker uploads volume, never in PostgreSQL. Local non-Docker storage is `backend/uploads`.

## iOS / EAS

Run `npm run ios` on macOS, or `npx eas-cli build --profile development --platform ios`. `eas.json` includes development, preview, and production profiles. Set your bundle identifiers, EAS project, production API URL, push credentials and signing before distribution. The shared code has no Android-only navigation or layout requirements. iOS signing and device verification were outside this pass.

Automated operations verification covers backend integration, migration round trips and browser workflows using an isolated database. See [verification evidence](documentation/smoke.md) and [implementation notes](documentation/implementation.md). The earlier Android smoke test predates the new camera and document-picker modules; rebuild and verify native devices before a pilot.
